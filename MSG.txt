fix(persistence): reject values the application would never write
# A hand-edited name no longer loads into a list nothing can find

The decoder checked that JSON had the right shape but not that the values
were ones this application produces. A list stored as " Work " loaded fine
and then could not be found by a lookup for "Work", and empty task
identifiers and titles were accepted and rewritten as valid data on the next
save.

Decoding now runs the same naming rules the application applies to its own
writes, and requires identifiers and list names to already be in their stored
form. Rejections name the path, leave the file in place for inspection, and
carry the reason. Everything this application writes still round-trips, so no
existing book becomes unreadable.

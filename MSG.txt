fix(cli): require --force before a task is deleted
# An irreversible removal now takes a second deliberate act

The specification asks for confirmation before deleting a task, and the
non-interactive command gave none: one mistyped reference removed the task
immediately, with no way back. Removing a populated list already required
--force, so the two destructive commands now behave alike.

The task is resolved first, so an unknown reference still reports the lookup
problem rather than asking the user to confirm a deletion that cannot happen.
Scripts pass --force, and the interactive interface keeps asking in a dialog.

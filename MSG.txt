fix(tui): keep the open list visible in the sidebar
# Scrolling the highlight into view also covers creating and deleting lists

The sidebar was never scrolled, so navigating a long list of task lists
moved the open list off screen while its tasks stayed visible. At eighty
columns with thirty lists, the selected name was nowhere on the display, so
the screen stopped saying which list was open.

The sidebar is now revealed whenever the current list changes, not only
when it has keyboard focus. The jump is deferred to the end of the frame
because creating or deleting a list leaves the scroll extent describing the
previous frame, and a jump measured against that gets clamped back to a
position that hides the row being revealed.
